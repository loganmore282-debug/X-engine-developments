# Petro audit — 24 September 2026

## Fixes

- Restored missing Home balance and reward-popup helpers that raised runtime errors.
- Removed three duplicate late script overrides. Withdrawal wallet loading now updates the wallet section without clearing the typed amount or overwriting a newer screen.
- Added a 45-second request deadline, including authentication token refresh. A session change before sending cancels the request; payment requests are never automatically retried.
- Protected payment submission against repeated taps and cleanup after navigating away. A configured zero withdrawal fee stays zero.
- Rewrote deposit guidance as three payment steps and withdrawal guidance as receiving-account, amount, availability, and tracking information. Values use current settings.
- Moved new referral commissions to the first confirmed, wallet-credited deposit, preserving the existing one-time rule. New investments do not trigger commission. Existing paid or pending legacy investment commissions remain intact; historical deposits are not retroactively rewarded.
- Made interrupted deposit credits durably retryable before moving money. Wallet credit tokens prevent repeated credit when subsequent record writes fail.
- Made Task Center claim tokens and wallet increments atomic. Retrying a claim repairs a missing transaction without paying again, even if team progress has since decreased.
- Kept deposit commission transaction links separate from deposit ledger links so deposit status repair cannot overwrite referral rewards.
- Rebuilt member and admin bundles with the existing guard and obfuscation. Member cache is v165; admin cache is v38.

Existing requested layout remains: My Assets below Home check-in, calendar check-in icon, individual full-width Task Center cards, muted thin scrollbar, direct password settings, and no activity feed.

## Verification

`npm run test:audit` runs the new payment fault-injection tests, source and guarded member DOM tests, and existing check-in, withdrawal-rule, and spin regression tests. These pass locally. Payment tests use an in-memory database and injected failures; member tests use JSDOM, not a real mobile browser.

Additional passing checks: PesaJet provider contract/signature/status tests with mocked responses; local HTTP static-server security headers, traversal protection and cache behavior; product schedules; CSS; referral requirements; referral/gift-code security; link-preview and country-delete tests. Both guarded builds pass syntax and compression round-trip checks.

Updated stale test fixtures to include current statement-ID dependencies, the PETRO_API_ORIGIN environment variable, and the remaining MarzPay/PesaJet providers. No production payment checks were relaxed to satisfy tests.

## Limits

This is a tested repair of reproduced problems, not a guarantee that every bug is eliminated. Other inherited suites still contain removed LipaPay/manual-payment features, old branding/layout expectations or obsolete extraction anchors and are not a clean full-suite gate.

Live HTTP probes to the member site on port 8080 and API /health on port 3000 timed out from this workspace. No real payment, production database write, or authenticated live mobile-browser test was performed. A GitHub push alone does not prove the VPS deployed successfully.

Keep the existing single PM2 instance: the application still uses process-local locks around multi-document operations. This change does not turn the database compatibility layer into an ACID transaction system.
